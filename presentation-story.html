CE / Custom evaluator contractImplemented

An evaluator is code with failure modes.

ConcisenessEvaluator / excerpt

def __call__(self, *, response: str,
             query: str = "", **kwargs):
    if self._model_config:
        score = self._llm_judge(query, response)
        if score is not None:
            return {"conciseness": score}
    return {
        "conciseness": self._heuristic(response)
    }

Abbreviated control flow. The source invokes _llm_judge with keyword arguments.

Rubric → JSON → score

Judge request: temperature 0, JSON object, 120 output tokens. Parse score; clamp to 1–5.

Rubric requires completeness as well as brevity. A short incomplete answer should not score well.

On judge failure: word count ≤ 50 returns 5.0, even for an empty response.

The prompt asks for a reason, but the callable returns only the score. Evaluation mode and reason are not preserved in that return value.

SourceRubric, callable, fallbackEvaluator tests

Walk: Keyword inputs match dataset columns; extra columns are accepted through kwargs. The judge prompt explicitly says short but incomplete is not concise. The response is parsed as JSON and the score clamped to the intended range.

Failure semantics: Exceptions return None; the callable switches to word count. That is a different metric under the same name. An empty response contains zero words and gets 5.0 from the heuristic. This demonstrates availability of a score, not equivalence of methods.

Production design: Preserve score, reason, evaluator version, judge deployment, evaluation mode, and error status. Choose explicitly whether judge unavailability blocks a release or yields an inconclusive result. Calibrate both modes separately if you retain both.

The exact failure policy

    status = ThresholdStatus.PASS
elif score >= threshold - warn_margin:
    status = ThresholdStatus.WARN
else:
    status = ThresholdStatus.FAIL

4.0 or abovePASS

Below 3.5FAIL / exit 1

What is actually checked?

Known names: groundedness, coherence, relevance, fluency, safety.

gpt_ is stripped before matching. Unknown metrics are skipped.

Conciseness has no absolute threshold entry. Safety submetrics need an explicit mapping.

An empty set of threshold results has no failures. Missing evidence needs its own check.

SourceThreshold policyThreshold unit tests

Trace: check_all_thresholds iterates the scores that arrived, removes gpt_, and checks only names in get_thresholds. It does not require every expected metric to be present. any_failures only looks for FAIL.

Work the examples: With threshold 4.0 and warning margin 0.5, 3.7 warns but does not block; 3.4 fails. Display-table emoji logic is separate from this policy.

Technical lesson: Evaluator registration, aggregation, and gate coverage are three distinct contracts. Running content safety does not establish that each returned risk submetric is governed by the generic safety threshold.

Recommended extension: Assert required canonical metrics, finite values, sample coverage, and the correct direction before applying thresholds. These are design recommendations, not code changes. Move by 21:00.

CE / Relative quality gateImplemented

What does “no regression” mean?

for evaluator in sorted(current.keys()):
    base_score = baseline.get(evaluator, 0.0)
    curr_score = current[evaluator]
    delta = curr_score - base_score

    if delta < -regression_threshold:
        status = "REGRESSION"
        has_regression = True

Default tolerance: 0.3 points.
Opening fixture: 3.2 − 4.7 = −1.5.

Read the edge cases

Only current keys are compared. Missing current metrics are skipped.

A newly appearing metric gets baseline 0.0.

No baseline file? Copy current results into it; first run passes without a comparison.

All deltas are treated as higher-is-better. Normalize risk rates and score scales before using a common policy.

SourceComparison logicRegression tests

Point: A comparison has assumptions about identity, coverage, direction, and scale. The code uses a strict less-than test. Do not confuse 0.3 points on a five-point score with 30 percent or a statistical significance test.

Ask: What if groundedness disappears after an SDK upgrade? Since iteration uses current keys, it is skipped. This accommodates name drift but does not verify required metric coverage.

Baseline: Bootstrap is convenient locally; production needs an approved, versioned baseline tied to dataset, judge, rubric, and candidate. The workflow does not automatically persist an approved baseline update back to git.

SourceASGI spans + metric producerProviders + instruments

Walk: Lifespan calls setup_telemetry after worker startup. The raw ASGI middleware creates a SERVER span; chat creates the nested application span. Azure Monitor configuration enables exporters and attempts optional httpx instrumentation.

Do not overclaim: Agent Framework and model-call spans depend on effective SDK instrumentation. The local trace_agent helper is not applied to the handlers. A list of agent labels is not a trace tree.

Metric semantics: The duration is calculated around the entire run_orchestrator call and recorded for every listed agent. A per-agent grouping of that metric is still whole-request timing. Token usage has an instrument definition, but this chat path does not update it.

Privacy: query.preview stores up to 80 characters; truncation is not redaction. Do not enable sensitive prompt/completion capture by default in a production recommendation. Move by 37:00.

The feedback loop

1. Capture and minimize evidence.

2. Have a domain owner validate the label.

3. Reproduce on the old candidate.

4. Generate and judge the fixed candidate.

5. Retain the case and release evidence.

Re-scoring the same stored answer cannot prove that an agent fix works.

Example: Suppose a request produced an unsupported guarantee. Preserve the relevant evidence, not an entire raw conversation. A reviewer defines the required qualification and verifies the reference source.

Reproduction: Run the old and fixed candidate against the same case and grounding snapshot. Capture fresh responses before judging. Confirm the fix and check the surrounding slice, not just the one incident.

Governance: Record identity and provenance in an artifact rather than unbounded metric dimensions. Exclude secrets and PII; set retention and access. Hold back unseen cases to reduce overfitting to the regression suite.

Scope: This is a proposed operating model, not an automatic pipeline implemented by this repo. Move by 47:00.
